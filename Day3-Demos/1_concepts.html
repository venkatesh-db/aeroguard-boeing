Structured outputs: make the AI fill in a form

📝 Analogy: ask a person "tell me about the order" and you get a story. Hand them a form with boxes and you get answers your computer can use. A JSON schema is that form; validation checks the boxes; a retry sends the form back when it's wrong.

{ "name": string (required) "quantity": integer (1–100) "size": "S" | "M" | "L" "urgent": true | false }

💡 Typical loop: ask for JSON → parse → validate (e.g. with Pydantic) → if invalid, send the error back and retry (max 2–3 times) → if still invalid, return a safe error. Many LLM APIs also offer a built-in "structured output" / JSON mode that makes failures rarer, but you still validate.

API contracts: the agreement between screen and server

🔌 Analogy: a plug and a socket. As long as both follow the same shape, either side can be rebuilt. Change the shape on one side only, and nothing works. The contract is the agreed shape of every request, response and error.
📱 UI sends (request)
POST /api/v1/chat { "session_id": "abc-123", "message": "Hello!" }

💡 A good contract: clear names · typed fields (Pydantic models) · one error format · a version in the URL (/v1) · documented automatically (FastAPI's /docs). Breaking changes go into a new version.

Session memory: LLMs forget everything between messages

🐠 Analogy: an LLM is like someone with no short-term memory. Every message, you must hand them the notes of the conversation so far. Your backend keeps those notes per session_id and sends them each time.

💡 Store history in a database or cache keyed by session_id. When it gets long: keep the last N messages, or summarise older ones, so you stay inside the context window and keep costs down.
